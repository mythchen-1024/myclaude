# BMAD 工作流完整指南

> **BMAD (Business-Minded Agile Development)** - 基于角色的 AI 驱动敏捷开发自动化

## 🎯 什么是 BMAD？

BMAD 是一种企业级敏捷开发方法论，通过 6 个专业化 AI 智能体和质量门禁，将你的开发流程转变为全自动化工作流。

### 核心原则

- **智能体规划**：专业化智能体协作创建详细、一致的 PRD 和架构文档
- **上下文驱动开发**：将详细计划转化为超详细的开发故事
- **角色专业化**：每个智能体专注于特定领域，避免角色切换导致的质量下降

## 🤖 BMAD 智能体系统

### 智能体角色

| 智能体 | 角色 | 质量门禁 | 产出物 |
|-------|------|----------|--------|
| **bmad-po** (Sarah) | 产品负责人 - 需求收集、用户故事 | PRD ≥ 90/100 | `01-product-requirements.md` |
| **bmad-architect** (Winston) | 系统架构师 - 技术设计、系统架构 | 设计 ≥ 90/100 | `02-system-architecture.md` |
| **bmad-sm** (Mike) | Scrum Master - 任务拆解、迭代规划 | 用户批准 | `03-sprint-plan.md` |
| **bmad-dev** (Alex) | 开发者 - 代码实现、技术文档 | 代码完成 | 实现文件 |
| **bmad-review** | 代码审查员 - Dev 和 QA 之间的独立审查 | 通过/风险/失败 | `04-dev-reviewed.md` |
| **bmad-qa** (Emma) | QA 工程师 - 测试策略、质量保证 | 测试执行 | `05-qa-report.md` |

## 🚀 快速开始

### 命令概览

```bash
# 完整 BMAD 工作流
/bmad-pilot "构建带支付集成的电商结账系统"

# 工作流：PO → Architect → SM → Dev → Review → QA
```

### 命令选项

```bash
# 跳过测试阶段
/bmad-pilot "管理后台" --skip-tests

# 跳过迭代规划（架构 → 开发直达）
/bmad-pilot "API 网关实现" --direct-dev

# 跳过仓库扫描（不推荐）
/bmad-pilot "添加功能" --skip-scan
```

### 单独使用智能体

```bash
# 仅产品需求分析
/bmad-po "企业 CRM 系统需求"

# 仅技术架构设计
/bmad-architect "高并发分布式系统设计"

# 编排器（可转换为任何智能体）
/bmad-orchestrator "协调多智能体复杂项目"
```

## 📋 工作流阶段

### 阶段 0：仓库扫描（自动）
- **智能体**：`bmad-orchestrator`
- **输出**：`00-repository-context.md`
- **内容**：项目类型、技术栈、代码组织、约定、集成点

### 阶段 1：产品需求（PO）
- **智能体**：`bmad-po` (Sarah - 产品负责人)
- **质量门禁**：PRD 评分 ≥ 90/100
- **输出**：`01-product-requirements.md`
- **流程**：
  1. PO 生成初始 PRD
  2. 系统计算质量评分（100 分制）
  3. 如果 < 90：用户提供反馈 → PO 修订 → 重新计算
  4. 如果 ≥ 90：用户确认 → 保存产出物 → 下一阶段

### 阶段 2：系统架构（Architect）
- **智能体**：`bmad-architect` (Winston - 系统架构师)
- **质量门禁**：设计评分 ≥ 90/100
- **输出**：`02-system-architecture.md`
- **流程**：
  1. Architect 读取 PRD + 仓库上下文
  2. 生成技术设计文档
  3. 系统计算设计质量评分
  4. 如果 < 90：用户提供反馈 → Architect 修订
  5. 如果 ≥ 90：用户确认 → 保存产出物 → 下一阶段

### 阶段 3：迭代规划（SM）
- **智能体**：`bmad-sm` (Mike - Scrum Master)
- **质量门禁**：用户批准
- **输出**：`03-sprint-plan.md`
- **流程**：
  1. SM 读取 PRD + 架构
  2. 拆解任务并估算故事点
  3. 用户审查迭代计划
  4. 用户确认 → 保存产出物 → 下一阶段
- **跳过**：使用 `--direct-dev` 跳过此阶段

### 阶段 4：开发（Dev）
- **智能体**：`bmad-dev` (Alex - 开发者)
- **质量门禁**：代码完成
- **输出**：实现文件
- **流程**：
  1. Dev 读取所有先前产出物
  2. 按照迭代计划实现功能
  3. 创建或修改代码文件
  4. 完成实现 → 下一阶段

### 阶段 5：代码审查（Review）
- **智能体**：`bmad-review` (独立审查员)
- **质量门禁**：通过 / 有风险通过 / 失败
- **输出**：`04-dev-reviewed.md`
- **流程**：
  1. Review 读取实现 + 所有规格
  2. 执行全面代码审查
  3. 生成审查报告及状态：
     - **通过**：无问题，进入 QA
     - **有风险通过**：记录非关键问题
     - **失败**：关键问题，返回 Dev
  4. 更新迭代计划并记录审查结果

**增强审查（可选）**：
- 通过 Codex CLI 使用 GPT-5 进行深度分析
- 通过 `BMAD_REVIEW_MODE=enhanced` 环境变量设置

### 阶段 6：质量保证（QA）
- **智能体**：`bmad-qa` (Emma - QA 工程师)
- **质量门禁**：测试执行
- **输出**：`05-qa-report.md`
- **流程**：
  1. QA 读取实现 + 审查 + 所有规格
  2. 创建针对性测试策略
  3. 执行测试
  4. 生成 QA 报告
  5. 工作流完成
- **跳过**：使用 `--skip-tests` 跳过此阶段

## 📊 质量评分系统

### PRD 质量（100 分）
- **业务价值** (30)：清晰的价值主张、用户收益
- **功能需求** (25)：完整、明确的需求
- **用户体验** (20)：用户流程、交互模式
- **技术约束** (15)：性能、安全、可扩展性
- **范围与优先级** (10)：清晰边界、必需 vs 可选

### 架构质量（100 分）
- **设计质量** (30)：模块化、可维护性、清晰度
- **技术选型** (25)：合适的技术栈、理由充分
- **可扩展性** (20)：增长处理、性能考虑
- **安全性** (15)：认证、授权、数据保护
- **可行性** (10)：实现现实性、资源匹配

### 审查状态（3 级）
- **通过**：无关键问题，代码符合标准
- **有风险通过**：非关键问题，包含建议
- **失败**：关键问题，需要 Dev 迭代

## 📁 工作流产出物

所有文档保存到 `.claude/specs/{feature-name}/`：

```
.claude/specs/e-commerce-checkout/
├── 00-repository-context.md    # 仓库分析（自动）
├── 01-product-requirements.md  # PRD（PO，评分 ≥ 90）
├── 02-system-architecture.md   # 设计（Architect，评分 ≥ 90）
├── 03-sprint-plan.md           # 迭代计划（SM，用户批准）
├── 04-dev-reviewed.md          # 代码审查（Review，通过/风险/失败）
└── 05-qa-report.md            # 测试报告（QA，测试已执行）
```

功能名称从项目描述生成（kebab-case：小写，空格/标点 → `-`）。

## 🔧 高级用法

### 批准门禁

关键阶段需要明确的用户确认：

```
Architect: "技术设计完成（评分：93/100）"
System: "准备进入迭代规划？(yes/no)"
User: yes
```

### 迭代优化

每个阶段都支持反馈循环：

```
PO: "这是 PRD（评分：75/100）"
User: "添加移动端支持和离线模式"
PO: "更新后的 PRD（评分：92/100）✅"
```

### 仓库上下文

BMAD 自动扫描你的仓库以了解：
- 技术栈（语言、框架、库）
- 项目结构（目录、模块、模式）
- 现有约定（命名、格式、架构）
- 依赖关系（包管理器、外部服务）
- 集成点（API、数据库、第三方服务）

### 工作流变体

**快速原型** - 跳过非必要阶段：
```bash
/bmad-pilot "快速管理界面" --skip-tests --direct-dev
# 工作流：PO → Architect → Dev
```

**架构优先** - 专注设计：
```bash
/bmad-architect "电商微服务架构"
# 仅运行 Architect 智能体
```

**完整严格** - 所有阶段最高质量：
```bash
/bmad-pilot "符合 PCI 的企业支付网关"
# 工作流：Scan → PO → Architect → SM → Dev → Review → QA
```

## 🎨 输出风格

BMAD 工作流使用专门的输出风格：
- 创建阶段分离的上下文
- 管理智能体交接并明确边界
- 跨阶段跟踪质量评分
- 处理带用户提示的批准门禁
- 支持 Codex CLI 集成以增强审查

## 💡 最佳实践

1. **不要跳过仓库扫描** - 帮助智能体理解你的项目上下文
2. **提供详细描述** - 更好的输入 → 更好的输出
3. **与智能体互动** - 在质量门禁期间提供反馈
4. **审查产出物** - 确认前检查生成的文档
5. **使用合适的工作流** - 复杂功能用完整 BMAD，简单任务用轻量级
6. **保留产出物** - 它们作为项目文档和未来工作的上下文
